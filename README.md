# Куда исчезает зарплата?

Рабочий MVP бюджета в тенге: за пять шагов показывает свободные деньги, резерв на платежи, ежедневный лимит и прогноз до следующей зарплаты. Русский интерфейс, тёмная тема, адаптация под телефон и компьютер. Приложение не требует собственного аккаунта и сервера.

## Локальный запуск

Установите Node.js 22 или новее. Распакуйте архив и откройте терминал в папке `salary-compass`, где находится `package.json`.

```bash
npm ci
npm run dev
```

Откройте адрес из терминала. Исходный `index.html` нельзя запускать двойным щелчком — нужен HTTP-сервер Vite.

```bash
npm test
npm run build
npm run preview
```

`test` запускает Vitest. `build` проверяет TypeScript и создаёт статические файлы в `dist`. `preview` запускает собранную версию.

## Возможности

- Пять шагов настройки: зарплата, текущий остаток, обязательства, долги, средние расходы. Неизвестные данные можно пропустить; приложение не заменит их случайными числами.
- Приблизительный остаток: введённая сумма до зарплаты + зарплата − все введённые траты; результат помечается как оценка.
- Обзор с балансом, резервом, свободными деньгами, дневным лимитом, прогнозом остатка и даты обнуления, текстовым статусом риска.
- Создание, редактирование и удаление расходов и поступлений; категория, комментарий, дата, обязательность, история, поиск и фильтры.
- Долги и обычные платежи: статусы, отметка оплаты, связь с существующим расходом без повторного списания, добавление следующего платежа.
- Аналитика по периодам: доли категорий, топ-3, крупные расходы, обязательные и повседневные траты, сравнение при наличии истории.
- Сценарии: меньше тратить каждый день, доставка −50%, отложить необязательные покупки. Сценарии не меняют реальные данные.
- Демо запускается самостоятельно и работает в отдельном состоянии в памяти.
- Карточка для Threads скачивается как PNG. Зарплата, баланс и долг скрыты, пока пользователь отдельно не разрешит их показать.
- JSON-экспорт и импорт с подтверждением замены, валидация, резервная запись, предупреждение об отказе хранилища.

## Финансовая модель

Суммы хранятся целыми тиынами. Разрешено до 1 млрд ₸ на запись и до двух десятичных знаков. Некорректные числа, отрицательные расходы и пустые обязательные суммы отклоняются. Текущий остаток может быть нулевым или отрицательным.

1. **Баланс** = подтверждённый остаток + фактические поступления − фактические расходы начиная с даты подтверждения. Уже учтённые записи исключаются по идентификаторам. Старые операции остаются в аналитике, но не списываются повторно.
2. **Резерв** = неоплаченные обязательства с датой строго раньше следующей зарплаты. Просроченные платежи учитываются сегодня.
3. **Свободно** = баланс − резерв. Полный размер долга в эту формулу не входит.
4. **Лимит** = max(0, свободно) / число дней. Округляется вниз до тиына; на главном экране — вниз до целого тенге.
5. **Прогноз** = баланс − резерв − переменные расходы в день × число дней.
6. **Дата обнуления** определяется ежедневной симуляцией с платежами в соответствующие дни.

Оплата создаёт одну связанную операцию и снимает резерв. Повторная отметка ничего не меняет. Привязка уже записанного расхода не списывает деньги второй раз. Удаление связанной оплаты возвращает обязательство в ожидаемые. При подтверждении нового остатка все существующие записи считаются уже включёнными в него.

### Допущения и ограничения

- Календарная дата берётся с устройства. Интервал включает сегодня, но исключает день зарплаты. Прогноз считает каждый оставшийся день полным; внутридневная точность не обещается.
- Платежи в день зарплаты относятся к следующему периоду. При необходимости оплатить раньше поступления денег укажите соответствующую более раннюю дату.
- Будущая зарплата не зачисляется автоматически. Полученное поступление добавляется пользователем, в том числе через настройки зарплаты.
- Для двух выплат в месяц предложен интервал 15 дней; точную дату пользователь может изменить. Месячные переходы учитывают длину месяца, високосный год и переход года.
- Без остатка лимит неизвестен. Без темпа трат доступен лимит, но не точный прогноз остатка и даты обнуления.
- Среднее по истории появляется после трёх полных дней и хотя бы одной записи переменного расхода. Дни без записей считаются нулевыми: неполная история занижает темп. Можно задать собственное среднее. Пустая история не трактуется как доказательство нулевых расходов.
- Обязательные и связанные платежи исключаются из среднего. Не учитывайте продукты или транспорт одновременно в резерве и в ежедневных переменных тратах.
- Сценарии по категориям используют среднее соответствующих необязательных расходов из истории и не могут уменьшить общий темп ниже нуля.
- Красный статус означает дефицит; янтарный — неотрицательный запас меньше двух дней текущего темпа; зелёный — больший запас. Неизвестные данные имеют отдельный статус.
- Сравниваются периоды одинаковой длины при достаточной истории. Если записанных доходов нет, процент явно подписывается «от одной зарплаты», а не выдаётся за долю фактического дохода за период.
- Остаток долга справочный. Его нужно уточнять по банку: часть платежа может уходить на проценты. Новый ежемесячный платёж создаётся отдельным действием.

## Хранение и приватность

Ключ: `salary-compass:v1`, резервная запись: `salary-compass:v1:backup`. При повреждении основной записи приложение пробует последнюю валидную копию. Повреждённую запись можно скачать в настройках. Отказ чтения или сохранения отображается пользователю; при невозможности сохранения изменения остаются в памяти до закрытия страницы.

Изменения в другой вкладке обновляют текущую и закрывают незавершённую форму. localStorage привязан к браузеру и домену. Для переноса между устройствами или с Sites на Pages скачайте JSON и восстановите его на новом адресе. Очистка данных браузера удаляет локальную историю; на общем устройстве она доступна другим пользователям этого профиля.

Финансовые суммы не отправляются на сервер. Нет банковских подключений, внешней аналитики и внешних шрифтов. PNG создаётся локально через Canvas. Хостинг может вести стандартные журналы HTTP-запросов. Первая загрузка требует сети; service worker и гарантированная работа без сети в MVP не входят.

## Загрузка в GitHub

Через браузер:

1. Создайте новый репозиторий, например `salary-compass`; для начала можно выбрать Private.
2. Распакуйте ZIP и откройте папку с `package.json`, `src` и `public`.
3. В GitHub выберите **Add file → Upload files**, загрузите исходные файлы и папки. `package.json` должен быть в корне репозитория.
4. Не загружайте ZIP вместо исходников, `node_modules`, `dist` и личные копии бюджета.
5. Укажите сообщение `Initial working MVP` и нажмите **Commit changes**.

Через терминал: создайте пустой репозиторий без автоматически добавленного README, затем выполните в папке проекта:

```bash
git init -b main
git add .
git commit -m "Initial working salary budget MVP"
git remote add origin https://github.com/YOUR_LOGIN/salary-compass.git
git push -u origin main
```

Замените `YOUR_LOGIN` своим логином. Используйте стандартную авторизацию GitHub Desktop, Git Credential Manager или SSH. Не сохраняйте пароли и токены в проекте.

Для обновлений:

```bash
npm test
npm run build
git add .
git commit -m "Update budget app"
git push
```

## Cloudflare Pages

Это статическое приложение. Для приведённой инструкции выбирайте **Pages**.

1. Откройте **Workers & Pages** в Cloudflare.
2. Выберите **Create application → Pages → Import an existing Git repository**.
3. Подключите GitHub и выберите репозиторий.
4. Заполните настройки из таблицы.
5. Нажмите **Save and Deploy**. После успешной сборки появится адрес `*.pages.dev`.
6. Проверьте настройку бюджета, демо, расход и перезагрузку.
7. Новые push в основную ветку будут автоматически пересобирать сайт.

| Настройка                | Значение                                     |
| ------------------------ | -------------------------------------------- |
| Framework preset         | React (Vite)                                 |
| Production branch        | `main`                                       |
| Root directory           | Корень репозитория, где лежит `package.json` |
| Build command            | `npm run build`                              |
| Build output directory   | `dist`                                       |
| Environment variable     | `NODE_VERSION=22`                            |
| Отдельная deploy command | Не требуется для этого пути Pages            |

Для тестов при каждой публикации можно использовать build command `npm test && npm run build`.

Без GitHub: выполните `npm ci` и `npm run build`, создайте проект Pages через прямую загрузку и загрузите содержимое `dist`. Такой проект обновляется вручную. Для автоматической сборки из Git используйте путь выше.

Для статического Pages не требуется Worker-entrypoint или `compatibility_date`. Если появляется ошибка об этой настройке, проверьте, что выбран Pages, а не отдельная команда публикации Worker.

Проверенные официальные инструкции:

- [Cloudflare: React on Pages](https://developers.cloudflare.com/pages/framework-guides/deploy-a-react-site/)
- [Cloudflare: build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/)
- [GitHub: adding locally hosted code](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)

## Границы MVP

Нет банковской синхронизации, серверного аккаунта, процентной модели кредита и автоматического создания будущих обязательств. Прогноз основан на введённых данных. Все фактические операции пользователь подтверждает самостоятельно.
