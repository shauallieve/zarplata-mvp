# Дожить до зарплаты

Рабочий mobile-first MVP финансового калькулятора для Threads на **React + TypeScript + Tailwind CSS 4 + Vite**.

## Возможности

- Доступный остаток, дата следующей выплаты (локальная дата), разовые платежи и ежедневные расходы.
- Прогноз остатка к выплате, дневной лимит, запас дней, предупреждение о дефиците.
- Сценарии экономии с ползунками по каждой ежедневной категории.
- Добавление/удаление собственных расходов.
- Необязательное локальное хранение на устройстве в `localStorage`; кнопка сброса.
- Генерация PNG-карточки **1080 × 1350** для Threads без персональных денежных сумм; копирование подписи.
- Адаптивный интерфейс; без сервера, API, куки и аналитики.

## Запуск локально

Установите Node.js 20.19+ / 22+ и выполните:

```bash
npm install
npm run dev
```

Откройте локальный URL из терминала (обычно `http://localhost:5173`).

Проверка:

```bash
npm test
npm run build
npm run preview
```

## Как развернуть на Cloudflare Pages через GitHub

1. Создайте **новый пустой** репозиторий GitHub и загрузите в него **содержимое этой папки** (в корне должны лежать `package.json` и `index.html`).
2. В терминале внутри папки:

```bash
git init
git add .
git commit -m "Initial financial calculator MVP"
git branch -M main
git remote add origin https://github.com/USERNAME/dozhit-do-zarplaty.git
git push -u origin main
```

3. Cloudflare Dashboard → **Workers & Pages** → **Create application** → **Pages** → **Import an existing Git repository**.
4. Выберите репозиторий, укажите **Framework preset: React (Vite)** (или Vite), **Production branch: main**, **Build command: `npm run build`**, **Build output directory: `dist`**.
5. Нажмите **Save and Deploy**. После успешной сборки получите адрес формата `https://имя-проекта.pages.dev`.
6. Следующие `git push` в `main` автоматически обновляют сайт.

В качестве альтернативы можно собрать локально `npm run build` и загрузить готовую папку `dist` в **Cloudflare Pages Direct Upload** (выбирайте Pages, не Worker; не загружайте `src` вместо `dist`).

**Важно:** файл `wrangler.toml` не требуется для Pages Git integration. Ошибка `compatibility_date is required when uploading a Worker` означает, что выбрали путь развёртывания **Workers**, а не статических **Pages**.

Официальные инструкции: https://developers.cloudflare.com/pages/framework-guides/deploy-a-react-site/

## Формула

`дни = календарное расстояние от сегодняшней даты до даты следующей выплаты` (не включая день самой выплаты).

`доступно после платежей = текущий остаток - сумма разовых обязательных расходов`.

`дневные расходы после экономии = Σ(ежедневный расход × (1 − процент сокращения / 100))`.

`прогноз остатка = доступно после платежей − (дневные расходы после экономии × дни)`.

`дневной лимит = max(0, доступно после платежей / дни)`.

`запас дней = floor(доступно после платежей / дневные расходы)`; если ежедневные расходы нулевые, показывается `∞`.

Считаем, что указанные разовые платежи **ещё не оплачены**, а остаток — это фактически доступные деньги **сейчас**, не общая месячная зарплата. Затраты постоянны по дням. Непредвиденные расходы/задержки выплат/проценты по долгам не учитываются. Поэтому результат — прогноз, а не персональная финансовая рекомендация.

## Приватность

- Если переключатель выключен, финансовые данные живут только в памяти текущей вкладки.
- Если включен — сохраняются в `localStorage` текущего браузера. На общих устройствах лучше не включать.
- PNG содержит только вывод «хватит / не хватит», без зарплаты, сумм расходов и дефицита в тенге.
- Ни одна финансовая цифра не отправляется на сервер приложением.
- На хостинге могут обрабатываться стандартные технические сетевые журналы запросов к статическим файлам.
